How clean is OpenNeuro's metadata?

I checked the BIDS metadata of 150 randomly sampled OpenNeuro datasets against 21 rules, most taken from the BIDS specification and schema. About half pass without a single warning. Hard errors are uncommon. The weak spot is participant bookkeeping, and a handful of acquisition inconsistencies would quietly trip up a pooled analysis.

Where the problems are

Of the 148 raw datasets, 76 (51%) have no warnings or errors, 68 have at least one warning, and 11 (7%) have an error that breaks the standard. Most findings are about consistency across files (participants against data folders, sidecars against each other), which a check of one file at a time can miss.

Participants are the weak spot

28 datasets (19%) have no participants.tsv at all. The file is only RECOMMENDED by BIDS, but without it age, sex and group are simply not available to anyone reusing the data. Where the file does exist, 10 datasets list people with no data in the release, 5 have data folders for subjects the table never mentions, and 5 write participant_id without the required sub- prefix.

Small formatting slips are enough to break a join. In ds004226 the two sides differ only in zero padding. In ds001838 the table also drops the prefix, so its unpadded IDs match nothing:

Hard errors are uncommon and concentrated

All errors come from 11 datasets. In 4 of them the only error is the missing sub- prefix above. The rest:

  • ds004166: 213 EEG recordings with no sidecar at all, so fields BIDS requires (sampling rate, power-line frequency, task name) are undefined.
  • ds004348: 9 EEG recordings with no sidecar at all, so fields BIDS requires (sampling rate, power-line frequency, task name) are undefined.
  • ds006833: 32 fieldmap IntendedFor entries point at runs that are not in the dataset.
  • ds005065: 3 MEG recordings with no sidecar at all, so fields BIDS requires (sampling rate, power-line frequency, task name) are undefined.
  • ds005697: its one EEG sidecar is misnamed (sub-16task-..., missing an underscore), so no sidecar applies to the recording.
  • ds001541: participant IDs without the prefix, and the same participant listed on several rows.
  • ds003012: a participants.tsv row with a trailing tab, one column more than the header.

Each of these is cheap to fix and expensive to discover late, which is the case for checking metadata in a pipeline rather than at analysis time.

Same task, different acquisition

11 datasets mix acquisition parameters within a single task and acquisition label: repetition times for fMRI, or sampling rates for EEG, MEG and iEEG (differences under 0.5% are ignored as rounding). None of this breaks BIDS, and much of it is deliberate. Multi-site and clinical recordings vary by scanner or hospital. It still matters, because a pipeline that reads one TR or one sampling rate per task will be wrong for some runs.

The largest spread is in ds005003, where resting-state runs use 12 different TRs (2.16 to 3.53 s). In the iEEG dataset ds005522, recordings of a single task range from 500 to 2000 Hz.

.bidsignore files that ignore too much

A .bidsignore tells the validator which files to skip. In 5 datasets a pattern also matches core files such as the README or the dataset description. neurolake never ignores core files and reports the pattern instead.

  • ds004103 ends its ignore file with *, which matches every file. All of its data sits outside the checks, so it is reported once rather than counted as participants with no data.
  • ds006833 uses **/*dat*, which also matches dataset_description.json.

Are newer datasets cleaner?

Datasets whose latest snapshot is from 2024 or later are clean 61% of the time (47 of 77), against 41% for older ones (29 of 71). Fisher's exact test gives p = 0.02, but treat that as suggestive. An earlier version of the rules gave p = 0.07 on the same sample, so the result depends on which rules count, and a snapshot's year is when the dataset was last updated, not first published. The share without participants.tsv falls too (p = 0.06).

How this was done

  • Sample. Accessions ds000001 to ds007500 were shuffled with a fixed seed (2026) and probed in that order against OpenNeuro's DataLad mirrors on GitHub. The sample is the first 150 with a snapshot tag (650 probes). Every probe is logged, transient errors are retried rather than counted as missing, and the same seed reproduces the same list. The median dataset has 28 subjects (middle half 17 to 52, largest 608).
  • Data. Each dataset's latest snapshot was shallow-cloned. Metadata files live in git, while imaging data stays as git-annex pointers whose keys carry the file size, so no imaging bytes were downloaded.
  • Rules. Sidecar field levels come from the BIDS schema, and the inheritance principle follows the specification text, including the rule that only one sidecar may apply per folder level. That rule is reported as informational for datasets declaring a version before 1.7.0, when the inheritance principle was rewritten. The TR, sampling-rate and .bidsignore rules are heuristics of my own. .bidsignore is honoured, and derivative datasets only get file-integrity checks.
  • Checks on the checker. Running on real data exposed false positives in the first version. 8 such patterns are now test fixtures that must never be flagged. An independent pass then reproduced the sample and every headline number from scratch, and checked 14 findings against the raw files. All 14 were real. It corrected one description and found one .bidsignore artifact, both fixed here, and found no missed violations in five clean datasets.
Limits

This covers 150 of roughly 1,500 to 2,000 mirrored datasets, and only each one's latest snapshot. The rules cover the metadata problems that most often break reuse, not the whole specification, so this complements the official validator rather than replacing it. Metadata stored in git-annex was not fetched, and the affected files are marked unknown rather than missing.

Reproduce it

pip install -e .
neurolake discover-mirrors --sample 150 --max-id 7500 --seed 2026 \
    --log-file audit/probe_log.csv > audit/sample_ids.txt
neurolake ingest-mirror --from-file audit/sample_ids.txt --lake data/audit
neurolake transform --lake data/audit
python audit/analyze.py data/audit
python audit/render.py
